# 08 · 冲刺计划（闭园前尽量多玩 8 大必玩）

> 目标：**在 21:00 停止排队、21:30 闭园前，尽可能多地玩到勾选的项目，并告诉我每一项几点去最合适。**
> 实现：`shared/planner.js` 的 `planMustDo()`，精确枚举 + 分时预测 + 步行成本，纯函数、零依赖。

## 1. 它回答什么问题

- 我 10:30 才进园 / 现在 15:12，从当前位置出发，今天还能玩到哪几个必玩？
- 按什么顺序、几点到几号项目排队，总排队时间最短？
- 哪些项目今天铁定来不及，差多少时间？
- 每个项目「单独去」的话，今天几点去最空？

## 2. 目标函数（按字典序）

1. **闭园前玩完的项目数量最多**（8 项里能玩几个是几个）
2. 优先级之和最大（勾选顺序即优先级，先勾的更重要）
3. 最后一项结束时间最早
4. 总步行距离最少

`mode:'all'` 时改为「必须全部玩完，完成时间最早」；来不及就给出能玩最多的方案并明确提示。

## 3. 约束

| 项 | 规则 |
| --- | --- |
| 排队截止 | 到达时间必须 ≤ 21:00（21:00 之后不再入场排队） |
| 结束时间 | 离开项目必须 ≤ 21:30（默认不允许把计划排到闭园之后） |
| 波动 | 等待估计 = 分时曲线 × 今日热度 × 保守系数 1.15 |
| 已关闭 | `latest.json` 里状态非 `operating` 的项目直接排除，标记 `closed` |
| 身高 / 尊享卡 / 演出 / 吃饭 | 不纳入本算法（身高按 122cm 已满足处理；全部必玩都有尊享卡但默认不买） |

## 4. 算法一句话

8 个项目的「有序子序列」一共 **109,601 条**（每个子集 × 每种顺序），直接 DFS 全枚举，每毫秒能算上百条，所以不需要启发式——直接在合法时间线里挑字典序最优的那条，得到的是**精确最优解**。

- 时间线：`arrive = 上一项 leave + 步行`；`leave = arrive + 排队 + 体验`
- 等待插值：把 14 天分时曲线在 08:00–21:00 按小时做线性插值
- 今日热度：`heatFactor = 当前实时平均排队 ÷ 同一时刻历史平均`，clamp 到 0.6–3.0
- 缺数据兜底：没有曲线 → 用 `latest` 实测 → 再用 20 分钟

## 5. 怎么用

### 5.1 命令行

```powershell
# 现在出发，8 大必玩全选
node tools\plan8.js

# 假设 09:30 入园
node tools\plan8.js --at 09:30

node tools\plan8.js --json
```

### 5.2 代码里调用

```js
var Planner = require('./shared/planner.js');
var r = Planner.planMustDo({
  catalog: catalog,          // data/catalog.json

console.log(r.completed.count + '/' + r.completed.total, r.totals.finishLabel);
```

## 7. 局限与后续

1. **步行是直线距离 × 1.35 ÷ 75 m/min** 的近似，园区内绕路可能多 20–30%；坐标是官方 WAM 的 BD-09，相对距离够用。
2. **热度系数全园共用**：个别项目当天临时的设备故障（如热力追踪长时间高排队）不会单独反映，靠 `latest` 实时值兜底。
3. **等待用 10-04 ~ 10-17 的 14 天曲线**（国庆尾巴偏多），今天的特殊活动（万圣节/圣诞）会偏离。
4. 不做「先吃饭/看演出/休息」的插入，也不考虑尊享卡与身高过滤。
5. 下一步：游玩过程中每完成一项自动重排（已具备能力，页面后续接）；仿真对比 4 种策略的收益（见 docs/09）。

## V2 升级（2026-11-11）

按《上海迪士尼排队最优路线算法 V2.0 技术方案》把预测与比较部分替换为项目级模型，页面行为变化：

1. **每一行排队时间都带预测区间**：`排队 93 分（预测 93~104）`，P50 是平衡值，P80 是稳健值。
2. **新增「预测口径」切换**：平衡 P50 / 稳健 P80。稳健口径会把排队估高，适合「最后一项必须赶上 21:00 排队」的场景。
3. **算法拆成 5 个模块**：`forecast`（项目级预测）、`walking`（步行矩阵）、`scoring`（方案比较 + 风险）、`replanner`（重规划防抖）、`planner`（枚举 + 时间线），打包成单文件 `shared/bundle.js` 供 H5/小程序共用。
4. **步行优先走矩阵**：`data/walking-matrix.json`（30 项目 / 435 对，由球面距离 ×1.35÷75 推导，标注 `source: derived`；有实测可覆盖）。
5. **回测**：15 天 83,536 个预测点，V2 相比 V1 的 MAE 降低 15%~35%，Bias 从 +4 分钟降到 ≈0。见 `docs/11-backtest.md`。
6. **CLI 新增** `--risk balanced|robust`、`--lock a,b`、`--no-history`；会自动读 `data/model-config.json`、`data/walking-matrix.json`，并把当天 `data/history/*.jsonl` 的最近 3 小时观测喂给模型。

已知限制仍与上面一致；其中「临时停运自动重排」的触发函数 `shared/replanner.js` 已经写好并有测试，但页面还没接（下一步）。

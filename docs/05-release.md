# 上架微信小程序：操作指南与检查清单

> 目标：把 `miniprogram/` 这套代码发布成正式微信小程序（体验版 → 审核 → 线上版）。
> 本文按 2026-11 的微信规则编写；具体费用/次数以微信公众平台页面为准。
> 结论先说：**技术上能上架，但有 5 个硬门槛必须先解决**（主体、小程序备案、服务类目、数据域名、版权合规）。

> **⚠️ 只是自己用？不要走这套流程。** 打开 [README「自己用（不发版）：一条命令启动」](../README.md)：运行 `start_local.ps1`，手机连同一 Wi-Fi 打开网页版即可，免注册、免备案、免审核。若需要「电脑关机后手机也能用」，优先看 [docs/06-phone-only.md](06-phone-only.md) 的免费部署（GitHub Pages / Cloudflare Pages），也不用上架；只有当你要把小程序正式发给别人、走微信入口时，再回来按本文上架。

---

## 0. 先看清 5 个硬门槛

| # | 门槛 | 说明 | 谁来做 | 耗时 |
|---|---|---|---|---|
| 1 | 小程序主体 | 个人 / 个体工商户 / 企业。个人主体可选类目受限，**旅游类目通常要《旅行社业务经营许可证》**，个人一般拿不到 | 你 | 1–3 天 |
| 2 | 小程序 ICP 备案 | 2023-09 起，新小程序**必须先备案才能发布**。在微信公众平台提交，管局审核 | 你 | 约 1–3 周 |
| 3 | 服务类目 | 建议「工具 > 信息查询」或「旅游 > 旅游服务（需资质）」。类目选错会被驳回 | 你 | 1–2 天 |
| 4 | 数据下发域名 | 小程序 `wx.request` 只能请求 **HTTPS + 已 ICP 备案 + 不能带端口** 的域名。`raw.githubusercontent.com`、`cdn.jsdelivr.net` 都没备案，**不能用于正式版**（开发者工具可临时关闭校验） | 你 + 我 | 2–4 周（备案）|
| 5 | 版权/数据合规 | ① 名称、头像、简介**不要含「迪士尼」等商标**（未经授权会被驳回/投诉）；② 排队数据来自 queue-times 第三方聚合，公开分发前确认其使用条款并保留署名「Powered by Queue-Times.com」；③ 不要宣称「官方数据」 | 你 + 我 | 持续 |

> 现实建议：如果只是想自己用，**不必上架**——用开发者工具的「预览/真机调试」或「体验版 + 体验成员」就够，免备案、免类目。
> 若确实要公开上架：**企业或个体户主体**最顺；个人主体请先做类目预审（微信后台选类目时会提示所需资质，拿不准就先选「工具」类）。

## 1. 注册与认证（约 1–3 天）

1. 打开 <https://mp.weixin.qq.com> → 「立即注册」→ 账号类型选 **小程序**。
2. 用**未注册过公众号/小程序的邮箱**注册；按提示选择主体类型（个人/企业），上传主体证件。
3. 登录后完善「基本信息」：小程序名称、头像、简介、服务类目。
   - 名称：**避开「迪士尼」**，例如「乐园排队助手」「排队最优解」；名称全局唯一。
   - 头像/简介：不要用迪士尼角色形象，不要写「官方」「上海迪士尼官方数据」。
4. 企业主体做「微信认证」（约 300 元/年，以页面为准）；个人主体按页面提示完成认证/验证。
5. 在「设置 → 基本设置」里拿到 **AppID**（形如 `wx1234567890abcdef`）。

## 2. 小程序备案（约 1–3 周，可与第 1 步并行准备材料）

入口：公众平台 →「设置 → 基本设置 → 小程序备案」→ 去备案。

需要准备：
- 主体证件（营业执照/身份证）、负责人身份证 + 手机号；
- 负责人**人脸核验**（微信扫码）；
- 应急联系人信息；
- 小程序服务内容说明（写「提供乐园游乐设施排队时间查询与游玩顺序参考」这类中性描述）。

提交后由**省通信管理局**审核（1–20 个工作日）。**备案通过前不能发布线上版**，但可以先上传体验版测试。

## 3. 数据下发：把 JSON 放到能访问的地方（三选一）

当前代码里 `miniprogram/utils/api.js` 默认读本地 mock：

```js
var DATA_BASE_URL = 'https://raw.githubusercontent.com/OWNER/REPO/main/data';
var MOCK_MODE = true;   // 发布前必须改 false，并换成下面三种之一
```

### 方案 A：对象存储 + 已备案域名（最标准，推荐公开上架）
- 买域名（阿里云/腾讯云，几十元/年）→ 做 **ICP 备案**（免费，2–4 周）；
- 开 COS/OSS 存储桶，绑定该域名、开 HTTPS；
- 数据由 GitHub Actions 采集后**上传到存储桶**（在 `.github/workflows/collect.yml` 加一步 `coscmd upload` 或 ossutil，凭据放仓库 Secrets）；
- `DATA_BASE_URL = 'https://data.你的域名.com/data'`（桶内目录对应 `catalog/latest/forecast/hourly-stats` 四个 JSON）。

### 方案 B：微信云开发（免备案域名，最快能跑）
- 公众平台「开发 → 云开发」开通环境（按量付费，基础套餐约 19.9 元/月，以控制台为准）；
- 把四个 JSON 放**云存储**，小程序用 `wx.cloud.downloadFile` / 或云数据库读取；
- GitHub Actions 通过云开发 HTTP API（或云函数 HTTP 触发）写入；
- 优点：不用备案域名；缺点：代码要改数据层（`utils/api.js` 增加 cloud 分支），且国内云函数**不能**直连 queue-times（必须由 Actions 采集）。

### 方案 C：自建服务器（不推荐）
轻量云服务器 + Nginx + HTTPS 证书 + 备案域名；成本/运维都高于 A，除非你已有服务器。

> 注意：**实时性上限是 10 分钟**（queue-times 上游刷新频率 + Actions 定时精度）。页面请展示「数据更新于 X 分钟前」，并注明「第三方聚合数据，仅供参考」。

## 4. 上传代码前要改的 6 处

| 文件 | 改什么 |
|---|---|
| `miniprogram/project.config.json` | `"appid": "touristappid"` → 你的真实 AppID；`projectname` 可保留 |
| `miniprogram/utils/api.js` | `MOCK_MODE = true` → `false`；`DATA_BASE_URL` → 你的 HTTPS 数据地址（结尾不要带 `/` 后的文件名，代码按 `BASE + '/latest.json'` 拼） |
| `miniprogram/app.json` | `navigationBarTitleText` 可保留「排队最优解」；如名称含敏感词同步改 |
| `miniprogram/pages/settings/*` | 增加「免责声明/数据来源」入口与文案（见下） |
| 微信后台「开发 → 开发管理 → 服务器域名」 | `request 合法域名` 填你的数据域名（必须 HTTPS、已备案、无端口；每月修改次数有限） |
| 微信后台「设置 → 服务内容声明 → 用户隐私保护指引」 | 本项目**不上传**个人信息，偏好只存手机本地（`wx.setStorage`）；如实填写：不收集位置/通讯录/相册；如后续加定位需声明 `wx.getLocation` |

建议的免责声明文案（放设置页或「关于」）：

> 本小程序为个人学习作品，非上海迪士尼度假区官方产品。排队数据来自第三方公开聚合（Powered by Queue-Times.com），存在数分钟延迟，仅供参考；实际排队以现场为准。本小程序不提供票务、不收集您的个人信息。

## 5. 上传 → 提审 → 发布

1. 微信开发者工具 → 导入项目，目录选 `miniprogram/`，填 AppID。
2. 先「预览」扫码真机走一遍 6 个页面（首页/排行榜/清单/行程/预测/我的），确认：
   - 无「undefined」「NaN」「暂无数据」异常；弱网有加载失败提示；
   - 数据是**真实数据**而不是固定 mock（审核会看内容是否真实、可用）。
3. 点「上传」，版本号如 `1.0.0`，备注「首个版本：排队查询与推荐」。
4. 公众平台 →「管理 → 版本管理」→ 选刚上传的版本 →「提交审核」：
   - 填写功能页面路径、测试说明；如需登录（本项目不需要）提供测试账号；
   - 类目必须与功能一致；
   - 审核通常 1–7 天，可能 1–3 次驳回（按驳回理由改）。
5. 审核通过后点「发布」→ 线上版生效（可回滚）。

## 6. 高频驳回原因（提前规避）

- **类目不符/缺资质**：旅游类目要旅行社资质 → 改成「工具」类目，或换企业主体补资质。
- **内容不真实/测试数据**：`MOCK_MODE=true` 提交必被驳回；确保线上拉真实 JSON。
- **域名未备案/带端口/非 HTTPS**：开发者工具能跑不代表线上能跑，审核会真机验证。
- **侵犯商标/名称违规**：名称含「迪士尼」「Disney」、头像用角色形象 → 驳回。
- **功能不完整/白屏**：数据请求失败要有兜底文案与重试，不能白屏。
- **诱导分享/关注**：不要写「分享给好友解锁」。
- **未配置隐私指引**：有 `wx.setStorage`/收集信息时需在后台填写用户隐私保护指引。

## 7. 上线后运维

- GitHub Actions 定时任务：**公开仓库**的 Actions 分钟数免费；10 分钟一次约 4,300 次/月。
  - 注意：仓库 **60 天无提交**时 GitHub 会自动停用 scheduled workflow，需要手动启用或定期提交；
  - 建议加 `workflow_dispatch` 手动触发（已有），并在 Actions 失败时邮件通知。
- 数据监控：`data/latest.error.json` 出现即代表上一轮抓取失败（脚本不会覆盖上一份好数据）；可在 Actions 里加失败通知。
- 更新节奏：queue-times 上游约 5–10 分钟更新；页面展示 `fetchedAt`，超过 30 分钟标黄「数据可能滞后」。
- 版本迭代：改代码 → 上传 → 提审 → 发布；小程序审核有缓存，发布后建议强杀重进验证。

## 8. 上架检查清单（逐项打勾）

- [ ] 主体已注册、认证通过，拿到 AppID
- [ ] 小程序名称/头像/简介已避开「迪士尼」商标
- [ ] 服务类目与功能一致（工具/信息查询，或旅游+资质）
- [ ] 小程序备案已通过（管局审核完成）
- [ ] 数据域名已备案、HTTPS 可访问、后台已配置 request 合法域名
- [ ] `MOCK_MODE=false`，`DATA_BASE_URL` 指向真实数据，真机验证 30+ 分钟数据在更新
- [ ] 免责声明/数据来源/更新时间已在页面展示
- [ ] 用户隐私保护指引已填写（不收集个人信息则如实声明）
- [ ] 六个页面真机走查无 undefined/NaN/白屏，弱网有提示
- [ ] 提审版本号、功能说明、测试路径填写清楚
- [ ] 审核通过后发布，线上版强杀重进回归一遍

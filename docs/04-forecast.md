# 分时预测：最近 14 天的排队规律

> 数据窗口：**2026-10-04 ~ 2026-10-17**（14 天，1,706 个快照 / 45,705 条项目级样本）
> 数据来源：Queue-Times.com park 30 的 5 分钟粒度历史，经 GitHub 镜像仓库 `hjeee3-tech/shanghai-disney-waits` 下载
> 生成时间：2026-11-11 · 对应 `data/hourly-stats.json`（契约 §6）与 `docs/forecast-report.html`

## 1. 结论速览

| 问题 | 答案 |
|---|---|
| 全园大概几点人最少？ | **20:00 之后**。14 天平均排队 **18.3 分钟**，是 17:00 高峰（30.1 分钟）的 **61%**，少约 **39%** |
| 全园什么时候最挤？ | **17:00**（30.1 分钟），其次是 11:00（28.4）和 14:00（28.0） |
| 一天的大致形状 | 9 点开园最低 → 10–11 点快速爬升 → 午后高位平台 → **17 点最高** → 18 点后回落 → **20 点明显变空** |
| 八大必玩几点去？ | 全部 8 个项目的 14 天最空小时都是 **20:00**；但创极速光轮（57 分钟）、七个小矮人（51 分钟）即便 20 点也仍然要排近一小时 |
| 如果要冲必玩 | 17–19 点先玩不排队的项目/吃饭/看演出，**19:30 后集中冲必玩**；20 点后效率最高，但离 21:30 闭园只剩约 1.5 小时，最多排 2 个大项 |

## 2. 方法（为什么可信）

- 每个快照只统计 `is_open=1` 且 `wait_time` 为数字的项目（0 分钟也计入，关闭/停运不计入）。
- **两层平均**：先算「每个快照里所有开放项目的平均排队」，再按小时平均。这样不会被项目数量变化带偏（例如晚上部分项目关闭）。
- 小时桶：09:00–21:00 共 13 个；不足样本的小时给 `null`，不猜。
- **可靠性过滤**：参与「最空/最挤」评选的小时必须有 ≥ 7 天样本（14 天的 50%）。21 点只有 3 天数据（末班快照少），因此被排除——它虽然显示 18.0 分钟，但不作为结论。
- 工作日 / 周末分开统计；`forecast.json` 用同一窗口重建（08:00–19:00 共 12 桶，29 个项目有值）。

| 抱抱龙冲天赛车 | 20:00 | 46.2 | 16:00 | 89.4 |
| 小飞侠天空奇遇 | 20:00 | 13.7 | 14:00 | 38.2 |

要点：

- **同一时刻不同项目冷热差极大**：20:00 加勒比只要 7 分钟、小飞侠 14 分钟，但创极速光轮仍 57 分钟、七个小矮人 51 分钟。
- **大项的最优时段是「闭园前 1–2 小时」**：创极速光轮从 17:00 的 90 分钟降到 20:00 的 57 分钟（-37%）；热力追踪从 79.5 降到 29.6（-63%）；加勒比从 38 降到 7（-81%）。
- 小项目（加勒比、小飞侠、雷鸣山）白天也不算离谱，**适合中午/下午排队低谷穿插**，把 20 点后的时间留给两个大项。

## 5. 怎么用这份预测

1. 打开 `docs/forecast-report.html`（双击即可，无需服务器）：看全园柱状图 + 八大必玩折线，可切「全部/工作日/周末」。
2. 小程序「分时预测」页：同样的数据，支持逐个项目切换，标出「最空」小时。
3. 排行程时：
   - 白天（10–17 点）优先刷**排队短、离得近**的小项目，避开 17 点高峰去吃饭/看演出；
   - **19:30–20:00 之后**再冲创极速光轮 / 七个小矮人 / 热力追踪；
   - 闭园 21:30 前 30 分钟项目可能提前停止排队，别把大项压到 21:00 以后。
4. 结合实时数据（`data/latest.json` / 小程序首页）做当日修正：预测给的是「相对规律」，当天实况可能因天气、设备检修、限流而偏移。

## 6. 局限（务必知道）

- **镜像滞后**：GitHub 镜像最新只到 **2026-10-17**，距今天（11-11）约 25 天；这不是「最近 14 天到今天」，而是「最近可得的连续 14 天」。想要含今天的窗口需要自己持续采集（本机 HTTP/3 采集已在跑，数据进 `data/history/`）。
- 窗口含**国庆假期尾巴**（10-04~10-07），这几天客流偏高，可能让工作日平均略偏高。
- 只统计排队时长，不含「走到项目的时间」「演出场次」「尊享卡/预约等候卡」的影响；实际体验还受演出时刻表影响。
- 平均值的方差大：同一小时不同日子的排队可能差一倍，预测适合做「相对冷热」判断，不适合精确到分钟。
- 21:00 只有 3 天有效样本，已从结论中排除；如果你想看闭园前的数据，请继续累积历史。

## 7. 复现

```powershell
# 1) 下载镜像里最近 14 天 CSV
python collector\fetch_history.py --days 14
# 2) CSV → data/history/*.jsonl（UTC、closed 分类、id 映射）
python collector\import_history.py
# 3) 生成 data/hourly-stats.json（契约 §6）
python collector\build_hourly_stats.py
# 4) 用同一窗口重建 data/forecast.json
python collector\build_forecast.py --history-dir data/history --days 14
# 5) 生成可双击打开的曲线报告
node tools\report.js
```

产物：

- `data/hourly-stats.json`：13 个小时桶 × 30 个项目 + 全园，含最空/最挤/最空窗口
- `data/forecast.json`：工作日/周末各 12 桶（08:00–19:00），供小程序算法做「预测降价」提示
- `docs/forecast-report.html`：自包含图表报告（SVG，无外部依赖）
- `data/history/YYYY-MM-DD.jsonl`：每天的快照历史，供后续累积与重算

数据来自 Queue-Times.com（park 30 = 上海迪士尼乐园），经公益镜像仓库转发。本项目仅用于个人学习与行程参考，不商用、不转售、不再分发原始数据；请控制请求频率（历史文件一次性下载即可，实时接口 10 分钟级已足够）。

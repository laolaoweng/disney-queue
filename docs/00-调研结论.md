# 调研结论：能不能拉「神奇等候时间」的排队接口？

**一句话：能拉到实时排队数据，但不建议去逆向「神奇等候时间」或迪士尼官方 App 的私有接口——用公开的 Queue-Times 数据源，配合境外定时抓取 + 小程序本地推荐算法，就能做出你要的东西，而且合法、稳定、零服务器成本。**

---

## 1. 三条路线对比（都是 2026-11-11 在本机（中国大陆网络）实测的）

| 路线 | 可行性 | 实测结论 | 风险 |
| --- | --- | --- | --- |
| ① 逆向「神奇等候时间」小程序接口 | 技术上有机会 | 小程序请求走 HTTPS，需要在 PC 微信上挂代理抓包（Charles/Fiddler）+ 登录态；接口大概率带签名/时间戳/风控，且它本身也是二手数据 | 违反微信小程序平台规范、未授权访问、接口随时改；维护成本最高 |
| ② 迪士尼官方 App 接口 | 已基本不可行 | 老一代 `authorization.shanghaidisneyresort.com`、`apim.shanghaidisneyresort.com` **已无 DNS 记录**（NXDOMAIN）；crt.sh 里查到的 20+ 历史主机全部下线；官网 `cu.apigw.shanghaidisneyresort.com` 可访问但 **WAF 限流（429）** | 伪造 token 违反服务条款；批量请求会被封 IP |
| ③ 公开数据源 Queue-Times | ✅ 已验证 | `https://queue-times.com/parks/30/queue_times.json`（30 = 上海迪士尼乐园），32 个项目的实时状态，10 分钟级更新，字段极简，免费 | 中国大陆 **TCP/TLS 直连被重置**，但 **HTTP/3（QUIC/UDP 443）实测可用**：本机直接抓 200/4143 bytes（2026-11-11 10:32 实时数据，`last_updated` 距采集 <1 分钟）；小程序 `wx.request` 只支持 TCP，所以给小程序供数仍要靠境外中继或自己的 HTTPS 服务器 |

补充：官网自己的 `POST /steamboat-wam/api/rap/facility/list` 是**真的、能用的、还带简体中文名和经纬度**，但里面只有静态资料（344 个设施里 wait/queue/crowd 关键词出现 0 次），**没有实时排队**。它对本项目仍然重要——项目的官方中文名、坐标、尊享卡标记都从这儿来。

**实时数据能不能拿到？能，而且分两种「实时」：**

- **本机/自有服务器实时采集（2026-11-11 已验证）**：queue-times 是 Cloudflare 站点，TCP 443 被 RST，但 **UDP 443 的 QUIC/HTTP3 没被封**。`collector/h3_fetch.py` 用 aioquic 发 HTTP/3 请求，实测 `status=200, 4143 bytes`，`fetchedAt` 与上游 `last_updated` 只差几十秒 → `python collector/collect.py --transport auto` 就能拿到真·实时数据，配合 `install_task.ps1` 每 10 分钟自动刷新。
- **小程序端实时**：微信小程序只支持 TCP 上的 HTTP/1.1-2（`wx.request` 没有 QUIC），所以小程序自己抓不了 queue-times。必须由一条 HTTPS 链路喂给它：GitHub Actions 境外 runner（已内置，每 10 分钟 commit `data/latest.json`）→ raw/jsDelivr/对象存储+备案域名/微信云开发；或者你自己的境外小服务器反向代理。

其他试过但走不通的：`api.themeparks.wiki`（被墙）、`queue-times.com`（被墙）、`magic-tips.app`（Cloudflare 403）、`17disney.com`（已停止运营）、各类 APK 站（全部超时，包名 `com.disney.shanghaidisneyland_goo` 拿到但下不到包）。

## 2. 如果一定要抓「神奇等候时间」，大概要做什么（以及为什么我们还是不建议）

1. 准备一台装了证书的 PC 或 root 安卓机，用 Charles / mitmproxy 对微信进程抓包；
2. 在小程序里点开项目详情，从请求里拿到 host、路径、签名参数（通常是 `sign`/`nonce`/`timestamp` 之类）；
3. 分析签名算法（可能是 MD5/HMAC + 固定 salt，也可能有设备指纹），用 Python/Node 复现；
4. 拿它换来的数据做你自己的接口。

**工作量**：顺利的话 1–3 天；不顺利（风控/加密）可能一周也搞不定，而且对方一改就失效。**合规**：这是未经授权的接口访问，且你要把数据二次分发给用户，风险比自用高一个量级。所以本项目的结论是：**数据用 Queue-Times，精力花在推荐算法和体验上**——这才是你这个产品真正的差异化。

## 3. 推荐架构（本项目已实现）

**两条采集链路，共用同一套 `catalog/latest/forecast` 契约和同一个推荐算法：**

```
链路 A（给小程序供数，境外中继）
GitHub Actions（境外，每 10 分钟）
  └─ collector/collect.py --transport tcp 抓 queue-times park 30 → data/latest.json（原子写、失败不覆盖）
       └─ git commit + push
            └─ ① raw.githubusercontent.com（本机实测大陆可访问）
               ② jsDelivr CDN（低频文件）
               ③ 对象存储 + 备案域名（正式发布）
               ④ 微信云开发（免域名白名单）
                 └─ 微信小程序：拉 catalog/latest/forecast
                      └─ shared/recommend.js 本地算「现在去哪儿最优」

链路 B（本机/自有服务器实时，HTTP/3 绕过封锁）
collector/collect.py --transport auto（TCP 失败自动走 QUIC）→ data/latest.json
  ├─ Windows 计划任务（install_task.ps1，每 10 分钟 + -SyncMock 刷小程序 mock）
  └─ node tools/now.js → 命令行直接输出「现在该去哪个项目」
```

**为什么小程序端算而不是服务端算**：排队数据 10 分钟才变一次，算法是纯函数（毫秒级），放本地可以做到零后端、零并发成本、断网用缓存也能给出建议。你以后想接「实时人流预测」「用户协同过滤」，再把这个函数换成服务端调用即可，接口不用动。

## 4. 数据质量与局限（先知道，免得上线被吐槽）

- Queue-Times 的 `wait_time` 是**估算值**（社区/官方口径混合），和现场牌子可能差 5–15 分钟；
- 覆盖 32 个项目：加勒比海盗、创极速光轮、雷鸣山漂流、翱翔·飞越地平线、七个小矮人矿山车、疯狂动物城：热力追踪（含单人通道）等主力项目都在；
- 没有演出时刻表、餐饮、厕所、花车巡游时间——这些要另接官方 `schedule` 数据（官网 `/rap/schedule-times` 目前返回空，需要带日期参数，可作为下一步）；
- 没有「尊享卡当前可售/价格」，catalog 里只标了哪些项目支持尊享卡；
- 更新有 1–10 分钟延迟，闭园/临时停运的状态可能滞后；
- HTTP/3 通道在 2026-11-11 上海电信实测可用，但个别运营商/企业网络可能封 UDP 443；`--transport auto` 会自动回退，采集失败时保留上一份数据并写 `data/latest.error.json`。

这些局限都写进了小程序界面（数据更新时间 + 免责声明）。

## 5. 合规清单（个人项目也别踩）

- Queue-Times 免费数据要求标注来源（界面上写 **Powered by Queue-Times.com**）；
- 抓取频率 10 分钟一次，别并发；
- 迪士尼官方站点只抓静态元数据，低频、单次、带正常 UA，不要批量扫路径（实测会触发 WAF 429）；
- 不要拿数据做付费转售；
- 小程序上线前把「排队时间为第三方估算，仅供参考」写进「关于」页。

## 6. 下一步可以做什么

1. **接入演出时刻表**：官网 `/rap/schedule-times` 带 `date` 参数也许能拿到；拿到后把 `category: show` 的项目按场次时间加权。
2. **历史数据积累**：Actions 每次把最新快照追加到 `data/history/YYYY-MM-DD.jsonl`，两周后就能用真实数据训练分时段预测（替换目前的经验曲线 forecast）。
3. **多人协同**：朋友之间共享「当前位置/已玩项目」，推荐会更准。
4. **尊享卡决策**：手里有尊享卡名额时，决定给哪个项目用——这就是算法里 `premierAccess` 参数，已经预留。
